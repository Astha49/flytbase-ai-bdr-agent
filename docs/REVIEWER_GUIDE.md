# Reviewer guide

This is a local six-stage inbound sales intelligence workbench. See README for Windows setup and `ARCHITECTURE.md` for the shared Python engine. The application is inspectable; it contains no sending integration, hosted deployment or hidden agent framework.

## Zero-credit inspection

Install dependencies and run `python -m streamlit run app.py`. Keep **Read-only demonstration** selected. No keys are needed. A clean source checkout opens the included fictional example, clearly labelled as a simulation. The author's actual live records and private budget ledger are excluded. No repaired complete live acceptance is claimed.

1. **Command Center:** inspect buyer context, BANT priority versus completeness, six recorded stage states, review reasons and clearly separated usage/allowance figures. Open previous results locally if available.
2. **Account Intelligence:** inspect supplied qualification and public research by topic. Cleared findings are separated from unknowns; expand original sources and audit details.
3. **Sales Strategy:** inspect five conditional draft branches with purpose, trigger, next step and evidence; compare customer cases and routing. All drafts require human approval. No actual buyer follow-up is fabricated.
4. **AE Handoff:** check buyer identity, qualification, up to three supported insights, case and route recommendations, gaps and next actions.
5. **How It Works & Evidence:** inspect architecture, provider responsibilities, source registry, reading limitations and execution record. Source access is not semantic proof.

Use **Download readable report**, **Download source-backed run data**, and **Download AE handoff** on any page. These export the current recorded result without calling providers. Cached/replayed outputs retain their identity and dates.

## Offline validation and limits

`python -B -m pytest -q` blocks external networking. `python -m scripts.simulate_offline --output tmp/rehearsal` checks 19 sales/evidence/export outcomes using fictional source and audit fixtures. Public checkouts explicitly skip private-record regression cases. Those skips are not live passes.

The historical live run remains partial. Repairs address actual malformed audit paths, missing audit context, unrelated issuer reports, omitted-text quotation errors, misleading continuous-operation matches, capability overstatement and downstream warning propagation. A real regenerated run still needs inspection. Genuine private buying details, partner availability and site applicability may remain unknown.

Any later live work needs the owner's credentials, sufficient verified free-tier capacity, a separately approved application allowance and another launch approval. `APPROVED_CONTINUATION.md` describes the cache-only procedure. Opening the dashboard, loading an example, navigating, downloading, planning or approving a local budget does not itself invoke providers.
