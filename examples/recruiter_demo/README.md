# Recruiter demo: synthetic saved results, zero API usage

This folder is safe to include in the source package. It contains **fictional test data**, generated by the existing six-stage engine with external networking blocked. It does not contain the confidential assignment PDF, local credentials or any private live run.

Start by opening [the readable report](offline_simulation/report.md) directly in GitHub or VS Code. The [JSON result](offline_simulation/run.json) contains the same six outputs, evidence, queries, configuration and logs. [verification.json](offline_simulation/verification.json) records the 19 simulation checks. A complete **simulation** is not a successful live assignment run.

The lead, company, financial figures, case studies, partner and semantic-audit responses are invented fixtures. `amx.example` and `andes-field.example` are reserved example domains. FlytBase URLs containing `__offline_fixture__` are intentionally nonexistent test keys used to exercise the official-domain check. **Do not cite, open or present these as real publications or customer relationships.** Source access fields simulate inspected input; each inspection-method field explicitly says that no web page was accessed. Real mechanical citation, period/scope, scoring and routing checks still run.

## Inspect without any API key

```powershell
.\.venv\Scripts\python.exe -m flytbase_bdr.cli --replay .\examples\recruiter_demo\offline_simulation\run.json
```

To view the same data in the existing Streamlit interface, copy only the public simulation into the normal run folder. This does **not** change `runs/project_budget.json` or any historical run. Keep read-only mode selected. Do not redirect `RUNS_DIR` to obtain new quota headroom.

```powershell
New-Item -ItemType Directory -Force .\runs\offline_simulation | Out-Null
Copy-Item .\examples\recruiter_demo\offline_simulation\run.json .\runs\offline_simulation\run.json
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Open **http://localhost:8501**. The newest saved folder is loaded in **Read-only demonstration**. If needed, use **Open previous results** and select `offline_simulation`. The warning identifies the offline fixture; all six stage tabs, original source excerpts and downloads are available. No configured keys are required. Tests block provider construction while rendering and rerendering this result.

## Reproduce the simulation

```powershell
.\.venv\Scripts\python.exe -m scripts.simulate_offline
```

This regenerates only this public fixture. Temporary workflow checkpoints are isolated from the private ledger and deleted afterwards. The simulation's internal network guard rejects any accidental request, and its output is always `offline_test`. The production workflow never falls back to this fixture when a live request fails.
